# v1.0.7 审查问题修复

基线：正式标签 v1.0.7，提交 `02bee252d9eb1b6fca5bb0fffd3f38379f10a9ec`。
本批修复保持版本号 1.0.7，未创建新标签或发布安装包。

## 改动对应关系

| 审查项 | 修复 |
|---|---|
| 凭据缺少 Salt/Hash 时抛异常 | 解码前拒绝空字段；解锁入口隔离验证服务异常，继续保持锁定 |
| Toast/第二次启动恢复不完整 | 两个入口复用 RestoreFromTray，统一恢复任务栏、宿主状态和时钟，保留锁定分支 |
| 后台接入抢前台 | 后台首次显示前设置 Owner；普通/最大化窗口用 SW_SHOWNA，最小化窗口用 SW_SHOWNOACTIVATE；主动接入和弹出恢复保留原语义 |
| 回车重复验证 | 首次 await 前设置共享门闩，同时禁用密码输入和按钮；finally 统一释放 |
| 设置保存失败无提示 | Save 返回成功状态，写入异常发出 SaveProblem；设置页显示持久错误和重试按钮，成功后清除 |
| 旧解锁任务清除新锁定标记 | 每次锁定递增代际，旧恢复任务在 await 后核对代际；过时结果和异常均不覆盖新锁定 |
| 托管窗口被发现规则过滤 | 后台扫描和手动扫描传入 UI 线程快照；仅允许 Owner/HWND/PID/进程启动时间均匹配的托管主窗口通过 Owner 和最小尺寸过滤；保留弹窗过滤 |
| 锁定标记无法写入却无提示 | 保持当前会话锁定，独立显示重启保护未保存的警告，并提供保存重试 |

托管窗口可能暂时被设置成 1×1 后停放屏幕外，因此不能只放行 Owner 而继续用新窗口的尺寸门槛过滤它。停放尺寸也不能用来证明登录页已经变成主界面；窗口太小时保留其已知角色，显式登录标题/类名仍优先。

## 自动验证

需要 Windows 和 .NET 8 SDK。在仓库根目录执行：

```powershell
dotnet build .\JuChuang.csproj -c Release
dotnet run --project .\Tests\ArchitectureProbe\JuChuang.ArchitectureProbe.csproj -c Release
dotnet run --project .\Tests\BadgeProbe\JuChuang.BadgeProbe.csproj -c Release
dotnet run --project .\Tests\RegressionProbe\JuChuang.RegressionProbe.csproj -c Release
.\Tests\ValidateSettingsTypography.ps1
```

RegressionProbe 直接链接生产 MainWindow.Lock.cs，以可暂停扫描及替代宿主验证并发顺序；凭据、标记和设置使用真实服务与专用临时目录。窗口发现、非激活接入、托盘恢复及设置错误显示使用实际应用程序集，窗口发现仅针对独立测试进程。测试不会启动正式应用的客户端扫描；真实主窗口测试移除 Loaded 和原生监控初始化事件，仅使用屏幕外空窗口。测试程序会暂时激活自己的屏幕外窗口以验证恢复行为。

新增验证包括：

1. 正常密码、错误密码，以及缺字段/null/非法 Base64/错误长度/损坏 JSON。
2. 连续提交仅允许一次验证；恢复扫描暂停时再锁定，新标记保留；下一次正常解锁能清除标记；挂起计数配平。
3. 旧恢复扫描抛异常时，不覆盖新锁屏或重复挂起宿主。
4. 锁标记写入失败时出现警告，重试成功后标记存在且警告消失。
5. 设置创建失败时返回失败并通知；修复路径后重试保存内容正确。
6. 已接入测试窗口在连续扫描中仍可发现；错误 Owner、未登记窗口、错误 PID 和过时进程启动时间均被拒绝；普通及最小化后台接入不改变接入前的前台窗口。
7. 普通隐藏、最小化、普通激活参数和账号通知参数恢复时，任务栏、时钟、宿主状态一致。
8. 设置页保存失败显示错误与重试入口，重试成功后恢复正常提示。

内部路径覆盖仅用于测试，不改变正式运行时的默认路径。验证工作流仅构建和测试，权限为 contents:read，不发布。

自动测试不能代替微信/WhatsApp 原生交互验收。以下项目尚未在真实客户端上确认：

- [ ] 首次资料读取失败后本地资料就绪，后续扫描能补齐；同 HWND 登录/切换账号后状态更新正常。

真实客户端单击问题目前只修复了已确认的前台激活路径；其最终用户可见结果需按上述清单验收。
