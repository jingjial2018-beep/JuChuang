# JNest v0.3.18 Preview 测试清单

> 这是 v0.3.18 的未签名测试包。  
> 本轮重点验证品牌替换、账号拖拽排序、后台消息提醒和资料状态显示。  
> 不修改微信登录配置，不注入微信，不读取聊天正文。

## 建议优先使用哪个包

- **SelfContained-win-x64**：推荐直接测试，不要求电脑预先安装 .NET 8 Desktop Runtime。
- **FrameworkDependent-win-x64**：体积较小，需要本机已有 .NET 8 Desktop Runtime。

## 必测场景

### 1. 品牌与 Logo

检查：

- 主窗口标题为 JNest。
- 顶部品牌文字为 JNest。
- EXE 文件名为 JNest.exe。
- Windows 任务栏图标、窗口图标、系统托盘图标均为新的黑色手写 J + 珊瑚红圆点 Logo。
- 托盘悬停文字为 JNest。
- Release 包名使用 JNest 前缀。

### 2. 账号拖拽排序

步骤：

1. 至少打开两个微信和一个 WhatsApp。
2. 在左侧“账号与窗口”列表中拖动任意账号到新的位置。
3. 继续切换账号，确认窗口与账号卡片仍对应正确。
4. 关闭 JNest，再重新启动。

期望：

- 拖动后列表顺序立即改变。
- 当前选中的账号不会因为拖动而误切换。
- 昵称、头像、未读数、PID/HWND 归属不变化。
- 微信和 WhatsApp 可以自由混排。
- 重启后恢复上次保存的顺序。
- 新登录且尚未识别身份的微信可以先临时出现在列表中，身份识别后再回到保存位置。

### 3. 后台 / 最小化消息提醒

步骤：

1. 选中一个微信账号 A。
2. 将 JNest 最小化，或切换到 Chrome 等其他程序。
3. 给账号 A 发送新消息。
4. 再测试给未选中的微信账号 B 发送消息。

期望：

- 即使消息来自当前 SelectedEntry，只要 JNest 不在前台实际查看，该消息也应让 JNest 任务栏图标闪烁。
- 未选中账号的新消息同样应触发 JNest 任务栏闪烁。
- 不自动恢复主窗口，不抢前台。
- 微信自身提醒仍保留；本版本不做消息接管或静音。
- 左侧未读数字 / 红点归属正确。

### 4. 正常资料状态简化

检查微信昵称和头像均成功读取后的账号卡片。

期望：

- 正常完成后只显示“已嵌入”或对应窗口状态。
- 不再长期显示“资料已识别”。
- 如果头像尚未读取，应继续显示“昵称已识别 · 头像待缓存”。
- 资料识别中、缓存回退、兼容性问题和读取错误仍应显示对应状态。
- 右键“复制诊断信息”仍可正常使用。

### 5. v0.3.17 核心功能回归

检查：

- EV 思路微信多开仍可正常创建独立新进程。
- 新进程 PID 与新增账号卡片对应正确。
- Login → Main 窗口重建后账号不丢失。
- 同 PID 换号时昵称、头像、未读不串号。
- 手动弹出后不会被后台扫描自动抓回。
- WhatsApp 接入、弹出、重新接入正常。
- 未读数字 / 红点识别正常。

## 反馈建议

异常时优先提供：

1. 发生问题前做了什么操作。
2. 预期结果和实际结果。
3. 异常账号右键 → **复制诊断信息** 的内容。
4. 必要时补充 `%LOCALAPPDATA%\JuChuang\logs` 对应时间附近的日志片段。

请不要上传 contact.db、消息数据库、密钥或完整微信数据目录。
